# NCCC 小額支付平台通路名單

聯卡中心「小額支付平台」的門市直接刷卡時，請款方是 NCCC 小額支付平台，多數銀行把這類交易（「小額支付特約商店」）排除在一般消費之外。這個目錄放名單與品牌對照表，讓網站在用戶搜到這些品牌時提示。

## 檔案

| 檔案 | 誰維護 | 內容 |
|---|---|---|
| `merchants.csv` | 自動（每週排程） | 聯卡中心的門市清單原檔，Big5 轉 UTF-8、內容未改，約 2 萬列。**網站不讀這個檔** |
| `source.json` | 自動 | 這一版名單的「截至」日期、ETag、下載日、列數 |
| `brand-map.csv` | **人工** | 品牌對照表：哪些品牌要收、級別、搜尋別名、怎麼從門市清單認出它 |
| `summary.json` | 自動（生成器） | 各品牌門市數＋對照表沒收但列數多的名稱。每週 PR 看它的 diff |
| `../../js/micropayment-brands.js` | 自動（生成器） | **網站讀的檔**：一個品牌一行（品牌名、級別、別名、資料日期），不含門市。禁止手改 |

來源頁：https://www.nccc.com.tw/wps/wcm/connect/zh/home/BusinessOperations/CardBusiness/MicroPayment
（檔案網址 `/wps/wcm/connect/ed441cc0-d955-42ee-8e12-c85c78470993/SMALL_TICKET_PLATFORM_MERCHANTS.CSV?MOD=AJPERES`）

## 資料怎麼流到網站

```
聯卡中心門市清單 ─(tools/nccc-refresh.sh 下載轉碼)→ merchants.csv ─┐
                                                brand-map.csv ─┴─(tools/build-nccc-brands.js)→ js/micropayment-brands.js → 網站
Google Sheets「Merchant Payments」的 micropayment_note 欄 ─(exportToJSON)→ cards.data → 網站顯示的提示文字
```

- **哪些品牌算、算哪一級**：這個目錄決定（repo）。
- **提示文字寫什麼**：Google Sheets 決定。Merchant Payments 的 `_default` 列放通用提示；某品牌想要專屬文字，就在它自己那列的 `micropayment_note` 填。
- 前端行為（灰卡、提示區塊）的規則：`docs/project/cashback-engine.md` 第 10 節、`docs/project/ui-display.md` 1j 節。

## brand-map.csv 欄位

| 欄 | 說明 |
|---|---|
| 品牌 | 顯示用的品牌名 |
| 級別 | 只能填 `全門市` 或 `部分門市`。全門市＝幾乎每家都在名單上 → 排除這類交易的卡標「一般消費排除」；部分門市 → 標「可能屬於排除項目」。**不確定就填部分門市** |
| 搜尋別名 | 用戶會打的寫法，用「、」分隔，大小寫不拘。兩個字的別名只在搜尋詞完全相同（或後面接空白）時命中，避免「青山洋服」被當成青山 |
| 比對規則 | regex，對門市清單的「對外名稱」與「登記名稱」（全形轉半形、轉小寫後）比對，用來數門市 |
| 備註 | 判斷依據。店數多為印象值、未查證 |

改完跑 `node tools/build-nccc-brands.js`，連同生成的兩個檔一起 commit（preflight 會檢查有沒有忘記跑）。品牌在名單上變成 0 列時，生成器會自動不把它寫進網站檔，並在輸出裡標出來。

## 每週自動更新

`.github/workflows/nccc-refresh.yml` 每週三早上（台北時間）執行 `tools/nccc-refresh.sh`：

1. 讀來源頁的「截至○年○月○日」，跟 `source.json` 一樣就結束。
2. 不一樣 → 下載新名單、轉碼、重算，開一個 PR。PR 說明列出門市數變化大的品牌、消失的品牌、新冒出來的名稱。
3. 人看過 PR：需要時改 `brand-map.csv` 的級別或加新品牌，再合併。

頁面改版讀不到日期、或下載到的名單不完整時，排程會失敗並中止，不會改任何檔案（GitHub 會寄失敗通知）。

## 站長已決定的事

2026-11-13：

- 繞路建議（哪張卡配哪種支付）**擱置**，第一版不做。
- 提示顯示在搜尋結果上方的「商家付款方式」區塊；文字放 Merchant Payments 的 `micropayment_note` 欄（英文欄名），通用提示放 `merchant` 填 `_default` 的那一列。
- 排除「小額支付特約商店」的卡用現有灰卡墊底：全門市品牌標「一般消費排除」，部分門市品牌標「可能屬於排除項目」。部分門市品牌的提示文字自動帶「部分」兩字（文字裡寫 `{部分}`）。
- 前端品牌清單用 repo 靜態檔，每週由 GitHub Actions 檢查更新、開 PR。不走「1-監控清單」。
- 收錄 60 個品牌（全門市 15、部分門市 45）。原本列為待判斷的 11 個全部收、標部分門市：晨間廚房、六扇門、龜記、CoMeBuy、五桐號、鶴茶樓、Touch Cafe、鹿上點、邦柏智慧、JIT快速剪髮、24Hi。青山是飲料店，收。
- 2026-11-14 追加停車場與販賣機 14 個品牌，合計 74 個（全門市 16、部分門市 58）。Times 停車場標全門市（站長提供：全台 1,100 餘場，名單上 988 個地址）；其餘場數未查證，標部分門市。Times 不收單獨的「Times」別名，避免撞到其他商家。
- 2026-11-14 再加俥亭停車（名單上因 Big5 轉碼寫成「𡡞亭」），合計 75 個。嘟嘟房（中興嘟嘟房）查過不在名單上，不收——收了會對沒加入平台的商家出錯誤提示。

- 提示分兩層（2026-11-14 站長改版，原本整段攤開太長）：
  - 平常看到的一行，放 Sheets 的 `_default` 列：「此商家{部分}門市是聯卡中心「小額支付特約商店」。」

## 尚未查證、不得寫進文案的事

- 滙豐是否不排除小額支付。
- 感應支付視同實體卡的銀行條款出處。
- 單筆超過 1,000 元是否仍算小額支付交易。
- 各品牌的全台店數（對照表的級別依據是印象值）。
