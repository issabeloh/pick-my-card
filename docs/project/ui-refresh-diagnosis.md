# 「AI 感／不專業感」診斷與分批改善計畫（2026-11-15～16）

站長的問題：看了 HeyMax（新加坡）、AwardWallet（美國）之後，覺得本站「很有 AI 感、不專業、沒有厲害感」，
要在**不影響使用動線**的前提下改善；另外想知道 landing 該不該下架。

本檔是那一輪的診斷結論與待辦。**不會一次做完**——每做完一項就在第 3 節打勾並補日期。
動全站視覺（底色、頁首、頁籤、結果卡、色票）之前先讀這份，再讀 `docs/project/ui-display.md` 對應節。

> 本檔的數字都是 2026-11-15 當天量的快照（`styles.css` 統計、GA 數字、卡片數），動手前重新量。

## 2. 對照站的專業感來自什麼（依站長 2026-11-16 提供的首頁截圖）

先講前提：那兩張截圖都是**行銷首頁**，對應的是本站的 landing，不是工具頁。

- **HeyMax**：第一屏＝一句話講「你得到什麼」（Earn miles here. Travel anywhere.）＋一顆按鈕＋真人照片＋具體數字
  （25+ 計畫、70+ 航空、200,000+ 會員）。往下是航空公司 logo 牆、商家品牌色塊、用戶見證。全站幾乎只有深靛藍一個顏色，大量留白，幾乎沒有框線。
- **AwardWallet**：白底藍字。第一屏＝產品手機截圖＋一句話＋輸入框。**數字直接當標題**
  （Over 598 Loyalty Programs／227 Billion Points）。每個功能配一張真實產品截圖，最後有「Bank Level Encryption」。

共同點（＝專業感的來源）：

1. 內容直接鋪在頁面上，沒有外框盒子
2. 一個品牌色＋大量中性色，顏色只留給「可以按」和「有意義」的東西
3. 真實素材：產品截圖、卡面、合作方 logo
4. 具體數字當標題（厲害感主要來自「看得見的資料深度」）
5. 字級少、對比大，一個畫面一個焦點

本站其實有深度（16 家銀行 34 張卡、每日更新），但只出現在頁尾 12px 的「最後資料更新」。

### 3.1 頁籤為什麼怪、怎麼改

資料夾頁籤的比喻需要一個「資料夾」（原本那張浮起的白卡）。去灰底之後頁首全幅，兩個頁籤各撐半個內容寬（1440 螢幕上各約 680px），看起來像兩顆巨大的按鈕。

- 方案一：頁籤改到白底、底線式，靠左、寬度依文字。位置與順序不變。
- **方案二（站長 2026-11-16 選定，已實作）**：保留資料夾頁籤，只是不撐滿、靠左。改動最小。
- 手機版兩案都不動（手機上頁籤撐滿螢幕是合理的）。

### 3.4 第一批實際怎麼做的（2026-11-16）

- **全幅版面靠兩個 CSS 變數**（`styles.css` 檔頭 `:root`，那裡有完整註解）：`--page-w`（內容寬度上限，原本寫在 `.container` 的 max-width）、
  `--page-gutter`（內容到視窗邊的距離）。底色要滿版的區塊（頁首、推薦比較）把 gutter 加進左右 padding；其餘區塊 `max-width: var(--page-w)` 置中
- **3.2 的示意 CSS 沒有照抄**：示意用 `100vw` 算留白，正式版改用 `100%`（不含捲軸寬）；示意是疊覆寫，正式版直接改原規則並同步改檔尾密度區塊
- **最優卡的角標**：兩欄以上維持「卡名右側留 64px」；單欄（≤640px）改成角標自己一列、右邊還給卡名——
  否則 360px 手機上 9 個字的卡名加了縮圖會被擠成兩行（站長要求顧及）。實測 360／390／820／1280／1440／1920 六種寬度查「蝦皮」沒有卡名換行

## 4. 用品牌 logo 的使用權（不是法律意見）

- **文字名稱**（寫「LINE Pay」「街口支付」）：單純指稱對方的服務，屬商標法的合理使用範圍，沒問題

  但 logo 圖案本身有著作權，部分品牌的使用規範只開放給「接受該支付的商家」
- 要用的話：用官方原檔不改色不變形、尺寸小而一致、不暗示合作關係、頁尾加「各商標屬各該權利人所有」、收到要求就下架

- **分組的地方只有一個**：`index.html` 首屏路由 script 裡「全新訪客 → 轉去 landing」那個分支。符合原條件（沒有 `?start`、localStorage 全空）的人擲一次骰子，

- **「舊 landing 對上新行銷頁」比的是兩種介紹頁哪個好**，回答不了更前面的問題——新用戶需不需要先看一頁介紹才能開始用。
  5.1 的數字指向這個更前面的問題：會試算的人幾乎都是當場就試，四分之三的人沒走到工具
- **建議比的是「landing」對上「工具＋第一次來才出現的一小段引導」**：搜尋框上方一句話講這是什麼、三個點了就直接出結果的範例、連到 landing 的「看介紹」。
  做完 2-2、2-3 之後工具首屏已經有信任列和推薦活動，只差這一小段，工作量遠小於重做一整頁行銷頁
- 結果怎麼用：B 贏或平手 → 取消強制轉址，landing 留作介紹頁，要不要改成 HeyMax 式就不急；A 明顯贏 → 證明完整介紹有用，這時才值得投資新行銷頁，下一輪比新舊 landing
- 指標要補一個：範例一點就出結果的話，B 組的 `calculate_cashback` 會被墊高，主指標要排除範例帶出來的那一次，或改看 `view_card_detail` 與 7 天回訪
- **順序**：不必等「去 AI 感」全部做完才開始測。測試要四週，是最長的一段，引導做好就開跑；2-4、2-5 在測試期間照做——兩組最後用的是同一個工具，改動對兩組的影響相同。
  測試期間只有兩樣不能動：landing 本身、首次引導那一段（各只有一組看得到）
- HeyMax、AwardWallet 需要行銷頁，是因為產品在註冊之後；本站不用登入、打幾個字就有答案，兩者的處境不同

### 5.6 實際做出來的樣子（2026-11-16 實作，在 preview 等站長看；上線日＝分流開跑日）

- **分組**：`index.html` 首屏路由 script，常數 `PMC_AB_TOOL_SHARE = 0.5`（分到 B 的比例）。定案時改成 0 或 1
- **localStorage 鍵**：`pmc_ab_landing`（`A`／`B`）、`pmc_ab_sent`（`ab_assigned` 送過了）、`pmc_onboard_done`（引導看完了）、`pmc_ab_forced`（站長強制指定）。都是純字串，不走 `readLocalJSON`
- **站長看兩組的方法**：網址加 `?ab=A` 或 `?ab=B`（例：`/?ab=B`）。強制指定的不送 `ab_assigned`、不設使用者屬性，不會汙染數字。
  ⚠️ 用過 `?ab=` 的瀏覽器之後都不算進測試；想當一般訪客重來，要清掉本站的網站資料
- **事件**（工具頁走 Firebase Analytics、landing 走 gtag）：

  | 事件 | 參數 | 哪裡送 | 用途 |
  |---|---|---|---|
  | `ab_assigned` | `ab_group`＝A／B | A 在 landing、B 在工具，每人一次 | 漏斗步驟 1 |
  | （使用者屬性）`ab_landing` | A／B | 兩頁每次載入 | 區隔 |
  | `landing_cta_click` | `cta_position`＝skip／final | landing 的兩顆「開始使用」 | 5.3 缺的那個 |
  | `onboard_start` | — | 導覽開始 | B 組有多少人真的看到導覽 |
  | `onboard_example_click` | `example` | 第 1 步選了範例 | |
  | `onboard_dismiss`／`onboard_complete` | `onboard_step`＝停在哪一步 | 按「跳過」或 Esc／走完 | 看人在哪一步離開 |
  | `onboard_intro_click` | — | 第 1 步的「看完整介紹」 | |

- **導覽裡按出來的計算怎麼排除**：第 2 步用戶按的是真的「計算回饋」鈕，那一次 `calculate_cashback` 的 `surface` 是 `onboard_example`（`surface` 早就註冊成自訂維度了）。
  主指標的步驟 2 要加條件 `surface` 不等於 `onboard_example`，同時也排除 `merchant_page`
- **引導的形式：背景暗化、一次打亮一樣東西的四步導覽**（DOM 由 `js/home-ui.js`「首次引導」動態建立，步驟定義在 `ONBOARD_STEPS`）：
  1. 打亮搜尋框：「結帳前，先 Pick My Card。一鍵比較你的信用卡哪張回饋最高！」＋範例蝦皮／中華航空／Apple Pay（點了把字打進搜尋框，不計算）
  2. 打亮「計算回饋」鈕，用戶親手按（只有這一步的打亮區可以點）
  3. 打亮第一張結果卡：講這張卡上有什麼
  4. 打亮選卡的地方（桌機＝側欄選卡區；手機＝漢堡鈕）：講「只比較你有的卡」
- **第一版被站長否決**（2026-11-16）：在搜尋框上方加一塊說明＋三個「點了直接出結果」的範例鈕。理由：桌機手機都更亂、不知道要做什麼；
  點範例直接跳到結果區，不懂發生什麼事。站長指定改成暗化＋逐步打亮。**不要再做回「在工具畫面上多加一塊說明」**
- 每一步都有「跳過」；第 2 步起有「上一步」（回到第 1 步可以重選範例）。「看完整介紹 ↗」開新分頁
- **導覽期間收起的東西**：搜尋框裡的快捷選項（`html.pmc-onboard .quick-search-wrapper`），導覽結束還原；Search Hint（範例「中華航空」會跳，手機上會蓋到計算鈕），導覽結束時清掉；
  手機首訪的側欄「探頭」提示不演（`playSidebarPeekHint`）
- **暗化層的寫法是被 iPhone 逼出來的**：第一版用「洞本身的超大 box-shadow」壓暗，站長的 iPhone 13 Safari 畫面最下面有一截沒蓋到（桌機正常）。
  現在是一片比視窗四邊各多 400px 的 `.tour-dim`，用 clip-path 挖洞。⚠️ 這個環境只有 Chromium，改完**沒辦法在 Safari 上驗**，要請站長用手機看

  商家頁、embed 不出。A 組從 landing 點「開始使用」進工具**不會**看到導覽（那一組比的是 landing）
